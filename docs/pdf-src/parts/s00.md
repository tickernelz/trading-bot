# 1. Summary

**Goal.** A crypto trading bot that runs autonomously 24 hours a day on the owner's PC, starting from a demo (dry-run) with initial capital of Rp 2 million; profit is reinvested as capital. The goal of the early stage is to prove the system, not to earn income (plan section 1).

**What is built.**

- The Freqtrade engine on the owner's PC as a git submodule vendor/freqtrade (Docker recommended; native Windows or WSL2 if needed; tested in stage 0) with a rule-based 1-4 hour swing strategy that produces entry candidates.
- A diverse voter swarm as a filter: results are combined with the median; it may only cancel or reduce an entry, never add risk.
- A deterministic risk layer in code (daily and total loss limits, kill switch, position sizing); orders and exits are deterministic; AI does not control them.
- A multi-vendor decision model through the DecisionProvider interface (not only Jev); deepagents LLM backend; the providers used are those active in omp models.yml; model used during testing: deepseek-v4.1-flash-1017 on provider nutaraline for all LLM roles.
- A provider and key setup UI; keys come through environment variables or an uncommitted local config, no endpoint returns a full key, and keys can only be entered from the PC.
- A single YAML configuration file; all settings are configurable.
- A full-featured app: live chart, live actions, entry candidate preview, swarm per decision, controls, history, audit; a PWA panel (Android, iOS, desktop) through a small gateway with an HTTPS tunnel. The Freqtrade API is not exposed to the internet.
- A unique UI/UX, not the default look. The visual direction (a station information board meeting a seismograph paper strip) is the operator's decision, still open to correction by the owner (chapter 11 and the mockup appendix).

**What is not promised.**

- Profit every day cannot be guaranteed. What is guaranteed is the limit: the bot stops opening new positions when the daily loss exceeds the limit.
- Rp 100 thousand per day requires 5% per day on Rp 2 million: not realistic.
- The swarm and median are a measured filter, not an assumed source of profit. Evidence that an ensemble raises trading profit has not been found.
- During testing all voters use a single model, so the swarm in that phase only tests the machinery and adapters, not the value of the swarm.
- Bot on a PC: if the PC is off, asleep, restarted, or the internet is down, open positions are not protected (chapter 7.2). That is why dry-run comes first.

Status: no product code, accounts, API keys, or money have been touched. This document is only a plan; the stage 0 and 1 tasks are created after this plan (plan section 10). All numbers in the mockup are sample data, not real results.

## 1.1 Owner directives in effect

| Directive | Content |
|---|---|
| Capital and profit | Rp 2 million; profit is reinvested as capital |
| Analysis | uses news and social (social is enabled after Reddit access is verified in stage 0) |
| Mode | demo first |
| Decision model | supports many models, not only Jev |
| Swarm analysis | swarm and median |
| Configuration | everything configurable |
| LLM backend | deepagents |
| Loss limits | default 1% per day and 10% total, still configurable |
| Platform | runs on the owner's PC; all OSes; mobile through PWA |
| Compute cost | not a constraint; the cost limit is in the configuration, off by default |
| AI provider | whichever is active in omp models.yml |
| Test model | deepseek-v4.1-flash-1017 on nutaraline for all LLM roles during testing |
| Provider and key | there is a setup UI; keys via env or local config (revision 9), not in the repo |
| UI/UX | unique, not AI slop; impeccable skill; visual direction is the operator's decision, open to correction |
| Project | ~/Projects/trading-bot with git; Freqtrade as a submodule |
| Working mode | full autonomy: the operator decides, the owner corrects along the way; real money and pushes to a remote are outside the autonomous window |
| Scope | full features, including live chart, live actions, and live preview |
