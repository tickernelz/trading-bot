# Languages

English is the default everywhere. Indonesian ships alongside it, and more languages can be added without code changes beyond the registry rows and files named below.

## Language policy

- The README, every document under `docs/`, `PRODUCT.md`, `DESIGN.md`, code, identifiers, one-line docstrings, configuration examples and commit messages are English.
- Text in another language lives only in that language's catalog: `pwa/src/lib/locales/id.ts` (PWA), `gateway/locales/id.json` (push notifications). The analyst's language is a name in the English registry `swarm/tb_swarm/languages.py`; it has no catalog.
- Allowed exceptions elsewhere: Indonesian tax terms and regulation names (PPh, PMK 50/2025), the exchange name Indodax, and verbatim quotes of captured third-party or model output, marked as quotes (for example the analyst examples in `docs/gateway-api.md` section 16, captured with the analyst language set to `id`).
- The PWA starts in English. It does not read the browser language; the user picks a language on the Login or System screen and the choice is stored in `localStorage` (`tb.lang`).

## What the server sends

The server sends stable codes (the `code` field of an error, enum values such as `verdict` `allow`, `reduce`, `skip`, `effect`, `state`, `reason`) plus English text in the text fields. The PWA translates from the code through its own catalog and shows the server's English text when it does not know the code. Diagnostic text (logs, audit details, error messages) is English only.

Three server outputs are written in a language chosen separately from the PWA catalog:

| Output | Language comes from | Where the texts live |
|---|---|---|
| Push notifications | `lang` sent by the PWA when it subscribes (`POST /gw/v1/push/subscriptions`, `docs/gateway-api.md` section 11.3) | `gateway/locales/<code>.json` |
| Analyst reports and answers | `analyst.language` in the bot config (default `en`) | the model is told to write in the language name from `swarm/tb_swarm/languages.py` |
| Everything else the PWA shows | the PWA catalog | `pwa/src/lib/locales/<code>.ts` |

## Add a UI language

The full steps are in `pwa/README.md`, section "Adding a language". In short:

1. Copy `pwa/src/lib/locales/en.ts` to `pwa/src/lib/locales/<code>.ts`, rename the export and translate every value; keep each `{placeholder}`.
2. Add one row to `LANGUAGES` in `pwa/src/lib/locales/index.ts` (`code`, `nativeName`, `htmlLang`, `intlLocale`, `load`).
3. Run `npx svelte-check` and `npm test` in `pwa/`. `tests/i18n.test.ts` checks that every registered language has the same keys and placeholders as English.

A key missing from a catalog shows the English text. The language switch lists whatever `LANGUAGES` holds.

## Add a push notification language

1. Copy `gateway/locales/en.json` to `gateway/locales/<code>.json` and translate it. Keep the shape: `number` (`group` and `decimal` separators), `words` (the same keys as English), and `kinds` with exactly `fill`, `risk_breach`, `kill_switch`, `heartbeat_lost`, `quorum_failed`, `daily_summary`, each with a `title` and a `body`. Keep the `{placeholders}`.
2. Rebuild the engine image (`gateway/` is copied into it) and restart the gateway. The catalogs are read once at start, and the gateway refuses to start if one has the wrong shape or `en.json` is missing.

A subscription stores the language it asked for. `lang` is matched case-insensitively with `_` read as `-`, then by its primary subtag (`fr-CA` uses `fr`); an empty or unknown code uses `en`. For the PWA to send the new code, add the same language to the UI registry above; otherwise it sends its own language code and the gateway falls back to `en`. `tests/test_gateway_push.py` renders every kind in every catalog in `gateway/locales/`.

## Add an analyst language

1. Add one entry to `LANGUAGES` in `swarm/tb_swarm/languages.py`: the code as the key and the English name of the language as the value (for example `"ms": "Malay"`). The name goes into the analyst prompt ("Write the text in {language}").
2. Set `analyst.language: <code>` in the bot config. The config schema (`engine/settings.py`) and the analyst runner take their allowed codes from the same registry, so any other code is refused when the config loads.
3. Rebuild the engine image (the swarm package is copied into it) and restart the analyst service. `swarm/tests/test_languages.py` checks the registry against the types.

Only the free text written by the model changes. JSON field names, the `grounded` flag, tool names and error codes stay English. The report records the language it was written in (`language`).
